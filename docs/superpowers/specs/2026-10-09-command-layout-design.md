# A 段参数指令与 F 段控制指令重编码规格

## 1. 目标

统一板端与客户端的指令分区，避免参数调整被误当成效果切换，保证调整亮度或节奏时不停止当前效果、不清空灯带，并为后续参数和控制功能预留连续空间。

本次协议迁移同时完成以下事项：

- 将效果指令继续固定在 `0x00~0x09`，保留 `0x0A` 作为后续效果扩展入口。
- 使用 `0xA0~0xAF` 承载参数调整指令。
- 使用 `0xF0~0xFF` 承载控制指令，并按递增顺序分配。
- 将当前特殊握手指令从 `0xFF` 迁移到 `0xF0`。
- 增加 `F4` 设备重启和 `F5` 清除保存状态并重启指令。
- 保持响应码 `0x01~0x04` 不变，因为响应码属于返回方向的独立编码空间。

## 2. 不在本次范围内的内容

- 不修改现有效果指令 `0x00~0x09` 的语义和 payload 格式。
- 不占用 `0x0A`。
- 不改变 CRC4 算法、包头、长度字段、序号字段和包尾校验位格式。
- 不修改 ACK、重发、health 响应和 sync 响应的编码。
- 不为旧版 `FE/FD/FC/FF` 增加兼容别名。板端和客户端必须同步升级。

## 3. 指令空间

### 3.1 效果指令

| 范围 | 当前用途 | 本次处理 |
| --- | --- | --- |
| `0x00~0x09` | 清空、静态颜色、闪烁、渐变、呼吸、流光溢彩、矩阵等效果 | 保持不变 |
| `0x0A` | 未分配 | 继续预留给后续效果 |
| `0x0B~0x9F` | 未统一分配 | 本次不使用 |

### 3.2 参数指令

| 指令 | 名称 | payload | 语义 |
| --- | --- | --- | --- |
| `0xA0` | 设置全局亮度 | 1 字节 `brightness` | 设置当前显示的全局亮度，范围 `0~255` |
| `0xA1` | 设置全局节奏 | 2 字节 `timing_ms`，大端序 | 设置支持节奏调节的效果的帧间隔，单位毫秒 |
| `0xA2~0xAF` | 未分配 | — | 后续增加参数时按递增顺序使用 |

参数包仍然使用普通协议帧，带当前序号和 CRC4。参数包成功后必须返回普通 ACK，不能使用效果专用响应。

`timing_ms` 的协议取值为 `1~65535`。板端按照各效果的安全范围进行裁剪；动画实现允许使用 `1ms`，流光溢彩默认使用 `10ms` 帧间隔。客户端的节奏控件不再通过重新发送效果指令实现。

流光溢彩此前已经确定为固定、平滑的内部动画，因此客户端的节奏控件对流光溢彩禁用，`A1` 不改变流光溢彩的固定帧间隔。其他支持节奏的效果读取全局节奏参数。

### 3.3 控制指令

| 指令 | 名称 | 帧形式 | 语义 |
| --- | --- | --- | --- |
| `0xF0` | 握手 | 特殊握手帧 | 建立新会话；沿用当前握手帧结构，仅将 opcode 从 `FF` 改为 `F0` |
| `0xF1` | health | 普通协议帧 | 检测设备在线状态并恢复已有会话 |
| `0xF2` | sync | 普通协议帧 | 获取板端当前图案、颜色、模式、亮度和节奏等状态 |
| `0xF3` | maintenance | 普通协议帧 | 终止板端运行循环并进入维护/上传模式 |
| `0xF4` | restart | 普通协议帧 | 停止当前运行并调用 `machine.reset()` 重启设备，保留保存状态 |
| `0xF5` | reset saved state | 普通协议帧 | 删除 `state.bin` 保存状态文件后调用 `machine.reset()` 重启设备 |
| `0xF6~0xFF` | 未分配 | — | 后续控制指令按递增顺序使用 |

握手使用特殊帧，不参与普通数据包的序号、长度和 CRC4 流程；但其 opcode 统一纳入 F 段后，`0xFF` 不再作为握手入口。

## 4. 响应编码

响应编码保持现状，不与请求指令空间混用：

| 响应码 | 名称 | 语义 |
| --- | --- | --- |
| `0x01` | ACK | 指令或数据包已成功处理 |
| `0x02` | RESEND | 请求客户端重发指定序号的数据包 |
| `0x03` | HEALTH_RESPONSE | 设备在线且会话有效，同时携带板端期望序号 |
| `0x04` | SYNC_RESPONSE | 返回板端状态快照 |

## 5. 板端状态与并发语义

板端维护共享效果参数：

- `global_brightness`：当前全局亮度。
- `global_timing_ms`：当前全局节奏参数。

处理 `A0` 或 `A1` 时：

1. 校验 payload 长度和参数范围。
2. 在参数锁内更新共享参数及状态快照。
3. 不调用 `EFFECTOR.stop()`。
4. 不清空 NeoPixel 缓冲区。
5. 当前效果下一帧读取新参数并继续显示。

效果循环必须在每次绘制帧前读取最新参数。对于静态颜色和自定义矩阵，板端应基于当前缓存内容重新渲染亮度，而不是先清空再显示；对于动画效果，亮度和节奏变化应在下一帧生效。

模式切换仍然使用效果指令，允许按照现有生命周期停止旧效果、启动新效果。参数指令与模式切换指令的职责不能混淆。

## 6. 客户端行为

客户端协议常量和构造器改为新编码：

- 握手发送 `F0` 特殊握手帧。
- health 发送 `F1` 普通包。
- sync 发送 `F2` 普通包。
- maintenance 发送 `F3` 普通包。
- restart 发送 `F4` 普通包。
- reset saved state 发送 `F5` 普通包。
- 亮度滑块发送 `A0`，不重新应用当前模式。
- 节奏滑块发送 `A1`，不重新应用当前模式；流光溢彩模式保持禁用。

启动和重连流程保持现有策略：优先 health 恢复已有会话，失败后使用 F0 建立新会话；新会话建立后再执行 sync。进入维护模式后，客户端关闭数据连接，用户点击“恢复连接”时重新走 health/F0 流程。

## 7. 会话与序号

- `A0/A1` 使用当前数据序号，参与 ACK、丢包重发、防重放和 `FFFF -> 0000` 回绕。
- `F1/F2/F3` 按现有控制包规则处理；health/sync 用于恢复会话时不推进普通效果数据序号，维护指令按当前实现执行 ACK 后进入维护态。
- `F0` 新握手成功后，客户端和板端按现有约定重置数据序号和重传历史。
- 未知的 `A` 段或 `F` 段指令必须安全忽略或返回协议错误，不能进入效果队列。

## 8. 重启与清除状态

### 8.1 F4：重启设备

板端收到并通过序号、长度和 CRC4 校验后：

1. 停止当前效果循环，避免重启过程中继续写入灯带。
2. 向当前客户端返回对应序号的 ACK。
3. 短暂等待 UDP 响应发送完成。
4. 调用 `machine.reset()`。

重启不会删除 `state.bin`，因此设备下次启动时仍按现有持久化逻辑恢复状态。

### 8.2 F5：清除保存状态并重启

板端收到并通过协议校验后：

1. 停止当前效果循环。
2. 删除持久化状态文件 `PERSISTENCE_PATH`，当前实现对应 `state.bin`。
3. 文件不存在时视为清除成功，不因重复执行报错。
4. 清除成功后向客户端返回 ACK，并短暂等待响应发送完成。
5. 调用 `machine.reset()`。

清除状态只删除保存当前灯效的 `state.bin`，不删除程序文件、网络配置或其他用户文件。设备重启后应使用固件默认状态启动，不再恢复被删除的灯效状态。

如果状态文件删除失败，板端不得继续执行重启；由于当前协议没有新增错误响应码，客户端应通过超时或随后 health 失败识别本次操作未完成，板端记录错误信息供串口诊断。

## 9. 迁移策略

这是一次成对升级：先更新板端，再更新客户端，最后更新测试和协议文档。由于不保留旧别名，旧客户端不能连接新板端，旧板端也不能正确识别新客户端的 F 段指令。

代码、测试和文档中不得继续把 `FE/FD/FC/FF` 作为正式指令名；历史设计文档可以保留原始背景，但必须明确它们已经废弃。

## 10. 验收标准

- 板端和客户端常量均为 `F0/F1/F2/F3`，握手实际发送 `F0`。
- `A0` 修改亮度时，静态、矩阵、呼吸和流光溢彩均不发生清空或模式重启。
- `A1` 修改支持节奏的效果时，当前显示连续变化，不发生清空。
- 流光溢彩仍使用固定平滑帧间隔，客户端节奏控件不可用。
- 参数指令参与正常 ACK、重发、防重放和序号回绕流程。
- F 段未知指令不会误触发效果或维护模式。
- health 恢复、sync 同步、维护模式和恢复连接流程在新编码下全部通过。
- `F4` 能在 ACK 后调用 `machine.reset()`，且保留 `state.bin`。
- `F5` 能删除 `state.bin` 后 ACK 并调用 `machine.reset()`；文件不存在时也能正常重启。
- `F5` 删除失败时不重启，客户端能通过超时或 health 失败识别异常。
- 更新协议测试、客户端测试、板端静态检查和 JavaScript 语法检查后，完整测试通过。
