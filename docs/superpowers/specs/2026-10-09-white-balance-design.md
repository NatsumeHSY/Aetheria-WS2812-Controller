# WS2812 白平衡校正设计

## 目标

WS2812 的红、绿、蓝通道发光效率不一致，使用相同的逻辑 RGB 值时，实际视觉颜色会偏蓝、偏绿。因此需要加入可调的三通道白平衡增益，同时满足：

- 客户端和同步协议继续保存“逻辑颜色”，不保存已经校正过的颜色；
- 板端生成的动画、矩阵、静态颜色、呼吸渐变、流光溢彩和扫描线统一经过校正；
- 白平衡可在运行时调整，并且调整后不需要重新发送整个颜色或矩阵；
- 白平衡随板端状态持久化，客户端重新打开后可以同步显示；
- 保持现有协议的 A 段参数指令规划，不占用 F 段控制指令。

## 方案选择

### 方案 A：客户端发送修正后的 RGB

不采用。该方案会让客户端状态变成“校正后颜色”，会影响矩阵编辑、保存恢复和多客户端同步；板端内部生成的彩虹/扫描效果也无法自然覆盖。

### 方案 B：协议层统一转换 RGB

不采用。需要在客户端每一种颜色、矩阵像素和效果参数发送前都做转换，容易遗漏新命令，也容易在恢复或重发时发生二次校正。

### 方案 C：板端输出层校正

采用。所有逻辑颜色保持原值，板端在 LED 驱动的共同出口处应用白平衡。当前 `LedDriver.set_pixel()` 和 `LedDriver.fill()` 已经是主要输出入口，静态、矩阵和动画最终都会经过这里。

## 核心数据模型

增加板端全局状态：

```python
GLOBAL_WHITE_BALANCE = (255, 255, 255)
```

三项分别代表 R、G、B 通道增益，范围为 `0~255`：

```text
校正 R = 原始 R × white_r ÷ 255
校正 G = 原始 G × white_g ÷ 255
校正 B = 原始 B × white_b ÷ 255
```

白平衡和全局亮度都在板端输出时计算。逻辑颜色、快照颜色、矩阵颜色和同步返回值均保持未校正的原始 RGB。

初始默认值为 `(255, 255, 255)`，表示不改变当前行为。实际灯带校准后再降低蓝色、绿色增益。`(255, 190, 110)`可以作为首次试调参考，但不能作为所有灯带的固定标准值。

## 板端实现

### 输出层

在 `LedDriver` 内增加统一的颜色转换函数，并由 `set_pixel()`、`fill()`共同调用。转换顺序为：

1. 限制输入 RGB 到 `0~255`；
2. 应用白平衡通道增益；
3. 应用全局/局部亮度；
4. 写入 `NeoPixel` 缓冲区。

白平衡参数读取必须是一个原子快照，避免动画线程在一次像素输出中读到半更新的三通道数据。白平衡不修改 `current_state` 和 `LIGHT_SNAPSHOT` 中的逻辑颜色。

### 运行时参数指令

沿用 A 段参数指令，使用当前连续编号中的下一个空闲值：

```text
PARAM_BRIGHTNESS_COMMAND = 0xA0
PARAM_TIMING_COMMAND    = 0xA1
PARAM_WHITE_BALANCE_COMMAND = 0xA2
```

白平衡指令 payload 固定为三个字节：

```text
[R 增益, G 增益, B 增益]
```

板端收到后：

1. 校验 payload 长度和范围；
2. 原子更新全局白平衡；
3. 静态、矩阵等非循环模式立即重绘；
4. 循环效果由下一帧自动读取新参数；
5. 写入持久化状态；
6. 返回普通 ACK。

这样不会清空灯带，也不会重启当前效果。

### 持久化

持久化格式增加三个白平衡字节，并将持久化版本从 `1` 升为 `2`。解码器继续兼容版本 `1`：旧文件读取时使用 `(255, 255, 255)`，随后可以在下一次状态保存时升级为版本 `2`。

建议白平衡字段放在 timing 后、颜色列表前：

```text
magic | version | mode | brightness_min | brightness_max |
timing | white_r | white_g | white_b | colors | matrix | params | checksum
```

板端启动恢复状态时同时恢复白平衡和逻辑灯光状态，然后再执行重绘或启动效果。

### 启动和重置行为

- 普通重启：恢复白平衡；
- 断电重新上电：恢复白平衡；
- “重置设备”：删除状态文件，因此白平衡恢复默认值；
- 维护模式：不改变白平衡文件。

## 同步协议

同步版本从 `1` 升为 `2`，在 timing 后加入三个白平衡字节。客户端解码版本 `1` 时使用默认白平衡，解码版本 `2` 时读取板端实际值。

同步返回值仍然返回未校正的颜色和矩阵数据，另外返回：

```text
white_balance: [R, G, B]
```

这样客户端显示的颜色值代表用户设置值，而不是 LED 驱动后的 PWM 值。

## 客户端实现

### Controller / Bridge

增加：

- `PARAM_WHITE_BALANCE_COMMAND`；
- `build_white_balance_packet()`；
- `LEDController.set_white_balance(red, green, blue)`；
- WebUI bridge 的 `set_white_balance` 方法；
- `SyncSnapshot.white_balance` 字段和版本兼容解析。

发送失败时保持现有连接错误处理，不修改本地 UI 状态；发送成功后更新本地状态。

### UI

在“光线参数”中增加“白平衡”区域，包含：

- 红色校正滑块；
- 绿色校正滑块；
- 蓝色校正滑块；
- 每项显示 `0~100%` 或 `0~255` 的当前值；
- “恢复默认”按钮，将三项恢复为 `255`。

滑块改变时发送三通道完整值，而不是发送单个通道，以保证板端状态更新原子化。对于快速拖动，客户端应使用短 debounce，避免连续产生大量 UDP 参数包。

客户端启动时沿用现有 health/sync 流程：连接成功并完成 sync 后，用板端返回的白平衡值覆盖本地 UI 状态。客户端本地状态只作为板端不可用时的界面恢复数据，不作为板端真实值来源。

## 校准流程

首次校准建议：

1. 设置逻辑颜色为纯白 `#FFFFFF`；
2. 将 R 增益保持为 `255`；
3. 逐步降低 B，直到白光不再明显偏蓝；
4. 调整 G，使白光接近中性；
5. 用浅灰、黄色、青色和肤色等常用颜色复核；
6. 保存参数。

白平衡是线性通道比例校正，不能完全替代 Gamma 或色彩空间转换。如果后续仍有低亮度颜色偏差，再单独评估 Gamma 校正，不在本次改动中混入。

## 测试计划

### 板端

- 白平衡 `(255,255,255)` 与现有输出完全一致；
- 单独降低 R/G/B 时只影响对应通道；
- `set_pixel()` 和 `fill()`使用相同转换结果；
- 静态和矩阵模式运行时修改白平衡会立即重绘；
- 动画模式下一帧使用新参数且不中断循环；
- 白平衡持久化、断电恢复、旧版本状态兼容；
- 非法 payload 长度和值不会修改状态；
- `sync` 版本 1/2 解析行为符合预期。

### 客户端

- 参数包命令和三字节 payload 编码正确；
- sync 可以恢复白平衡并显示到三个滑块；
- 拖动参数不会改变逻辑颜色和矩阵数据；
- 重置设备后客户端收到默认白平衡；
- 断线、重连和健康检查不会重复或错误覆盖白平衡状态。

## 自审结论

- 白平衡放在板端输出层，覆盖范围完整；
- 协议颜色仍表示逻辑颜色，不会发生二次校正；
- 参数使用 A 段，不会占用 F 段控制指令；
- 已考虑持久化、同步、旧版本兼容和重置行为；
- 不依赖某一块灯带的固定校准值；
- 本设计不包含 Gamma 校正，避免把亮度比例和感知亮度问题混为一谈。
